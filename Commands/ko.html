외관
Wikven
이 문서는 Commands 문서를 번역한 것이며 번역은 100% 완료했습니다.
다른 언어:
  • English
  • 한국어

Wikven을 실행하는 모든 방법 — Docker 이미지, 단독 실행 바이너리, GitHub 액션 — 은 같은 빌드를 구동합니다. 이 문서는 그 셋 모두에 대한 참고서입니다. 무엇을 실행할 수 있고, 무엇을 전달할 수 있으며, 환경에서 무엇을 읽는지를 다룹니다.

작업 디렉터리

Wikven은 디렉터리 하나를 기준으로 동작하고, 나머지는 모두 거기서 파생됩니다:

<workdir>/src
여러분의 위키텍스트, 이미지, .wikven.yaml. 읽기만 하며, 번역 도우미를 쓸 때를 빼고는 쓰지 않습니다.
<workdir>/dist
빌드된 사이트. 빌드가 시작될 때마다 비워집니다.
<workdir>/.cache
일회용 데이터베이스와 MediaWiki의 임시 공간. 여러분의 사이트에 속하는 것은 없으며, 빌드 사이에 지워도 됩니다.

Docker 이미지는 작업 디렉터리가 /workspace이고, 그래서 빌드가 src와 dist를 그 아래에 마운트합니다. 바이너리는 현재 디렉터리를 씁니다. 어느 쪽이든 WIKVEN_WORKDIR이 이를 덮어씁니다.

build

src/를 dist/로 빌드합니다. 이미지의 기본 명령이므로 Docker 쪽은 인자가 필요 없습니다:

BinaryDocker

wikven build


docker run --rm \
  -v "$(pwd)/src:/workspace/src" \
  -v "$(pwd)/dist:/workspace/dist" \
  ghcr.io/chaotic-ground/wikven

옵션은 없습니다. 빌드에 알려 줄 수 있는 것은 모두 .wikven.yaml 파일에 있습니다. 실패한 빌드는 0이 아닌 값으로 끝나며 어느 문서나 단계에서 실패했는지 알려 줍니다.

serve

이미 빌드된 dist/를 로컬 미리보기용으로 8080 포트에서 제공합니다. 빌드는 하지 않으므로 build를 먼저 실행하십시오.

BinaryDocker

wikven serve
wikven serve --listen 127.0.0.1:3000


docker run --rm -p 8080:8080 \
  -v "$(pwd)/dist:/workspace/dist" \
  ghcr.io/chaotic-ground/wikven serve

--listen은 바이너리만 받습니다. 컨테이너는 안에서 항상 8080을 듣고, 바깥 포트는 Docker 자신의 -p로 정합니다.

translate

번역하기 뒤에 있는 네 가지 도우미입니다. 소스 트리를 대상으로 동작하며 아무것도 빌드하지 않고 끝납니다.

두 제품 모두에 있습니다. 이미지는 마운트된 소스 트리를, 바이너리는 작업 디렉터리를 대상으로 실행하며, 아래 두 형태의 차이는 그것뿐입니다.

translate mark
소스 문서에서 아직 표시되지 않은 단위에 <!--T:n--> 표시자를 넣습니다. 이미 있는 번호는 유지하므로 다시 실행해도 안전합니다.
translate scaffold <언어>
번역해 넣을 골격으로, 모든 원본 단위에 대해 빈 표시자를 <Page>/<언어>.wikitext에 씁니다. 이미 번역한 것은 유지합니다.
translate stamp
당신이 읽은 번역 하나에 대해, 그 단위들이 어느 원본 판을 보고 쓰였는지 기록합니다.
translate check
망가진 원본 문서와, 오래되었거나 빠진 번역을 보고합니다. 아무것도 쓰지 않습니다.

mark와 scaffold는 파일 하나를 받거나, 소스 디렉터리 아래 모든 문서를 대상으로 하는 --all을 받습니다. 이 둘이 쓰는 내용은 원본에서 유도되므로, 트리를 훑는 것이 파일을 지목하는 것보다 더 말하는 바가 없습니다. stamp는 파일 하나만 받고 --all이 없습니다. 이것이 쓰는 것은 도구가 유도할 수 있는 무엇이 아니라 당신의 읽기이고, 트리 전체를 한 번에 읽는 사람은 없기 때문입니다. check는 둘 다 받지 않고, 언제나 찾을 수 있는 모든 문서를 읽습니다. mark, scaffold, stamp는 소스에 씁니다. Docker에서는 쓰기 가능하게 마운트하고, 바이너리는 그 자리에서 바로 고칩니다. check는 읽기만 합니다.

BinaryDocker

wikven translate mark --all

wikven translate scaffold ko "Getting Started.wikitext"

wikven translate check --gate


docker run --rm -v "$(pwd)/src:/workspace/src" \
  ghcr.io/chaotic-ground/wikven translate mark --all

docker run --rm -v "$(pwd)/src:/workspace/src" \
  ghcr.io/chaotic-ground/wikven translate scaffold ko "Getting Started.wikitext"

docker run --rm -v "$(pwd)/src:/workspace/src:ro" \
  ghcr.io/chaotic-ground/wikven translate check --gate

check는 두 가지를 더 받습니다:

--gate
원본 문서가 망가졌을 때 0이 아닌 값으로 끝냅니다. 오래되었거나 빠진 번역은 어느 쪽이든 보고되지만 실행을 실패시키지는 않습니다. 번역은 영어 문서를 고친 사람의 몫이 아니기 때문입니다.
--path-prefix <접두사>
보고되는 파일 이름 앞에 접두사를 붙여, 컨테이너 안의 경로가 아니라 저장소의 경로로 읽히게 합니다.

환경 변수

WIKVEN_WORKDIR
위에서 설명한 작업 디렉터리. 이미지에서는 /workspace, 바이너리에서는 현재 디렉터리가 기본값입니다.
SOURCE_DATE_EPOCH
빌드가 자기 내용이 쓰였다고 밝힐 유닉스 시각으로, reproducible-builds 관례를 따릅니다. 빌드는 시계를 그 값에 얼린 채 실행되므로 출력의 모든 시각이 일정합니다. 설정하지 않으면 고정된 날짜를 씁니다. 매번 움직이는 날짜보다 틀렸더라도 움직이지 않는 쪽이 감당하기 쉽기 때문입니다. bake 액션은 빌드 중인 커밋의 시각으로 설정합니다.
WIKVEN_BUILD_JOBS
스킨 렌더링을 몇 개까지 나란히 돌릴지. 설정하지 않으면 쓸 수 있는 프로세서 하나당 하나씩 쓰는데, 호스트가 아니라 컨테이너에 허용된 몫을 따릅니다. 나란히 돌릴 렌더링이 있는 것은 스킨을 둘 이상으로 빌드한 사이트뿐입니다. 메모리가 부족한 기계이거나 로그를 순서대로 보고 싶다면 1로 두어 빌드를 차례대로 진행시키십시오.

둘이 더 있는데, 빌드가 스킨 하나의 렌더링을 실행하려고 스스로에게 설정하는 것들입니다. WIKVEN_BUILD_SKIN은 그 스킨의 이름이고, WIKVEN_BUILD_DB_DIR은 그 렌더링이 쓸 데이터베이스 사본의 위치입니다. 렌더링들이 나란히 돌아가는데 SQLite는 한 번에 하나만 쓸 수 있기 때문입니다. 둘 다 손으로 설정해서 쓸 일은 없습니다. WIKVEN_BUILD_DB_DIR은 WIKVEN_BUILD_SKIN이 설정되어 있을 때만 읽히고, 그 WIKVEN_BUILD_SKIN을 손으로 설정하면 빌드가 아무것도 채워지지 않은 위키를 렌더링하는 과정이 되어 빈 사이트를 씁니다.

bake 액션

GitHub Actions 러너에서 Docker 이미지로 소스 트리를 굽습니다. 완전한 워크플로는 배포하기를 참고하십시오.

두 액션 모두 태그로 고정합니다. Wikven의 버전이 릴리스되기 전까지 그 태그는 나이틀리, 곧 날짜가 붙은 사전 릴리스 nightly-YYYY-MM-DD이며, 가장 최근 것은 릴리스 페이지에서 고를 수 있습니다. 이미지도 같은 나이틀리로 함께 지정하십시오. 기본값에 맡기면 액션이 잘려 나온 릴리스의 이미지를 실행하는데, 아직 릴리스된 버전이 없습니다. 릴리스가 나온 뒤에는 @v1.2.3만으로 충분합니다. 태그에는 v가 붙고, 그때 액션이 기본으로 쓰는 이미지는 v 없는 :1.2.3입니다.

- uses: chaotic-ground/wikven/actions/bake@nightly-YYYY-MM-DD
  with:
    source: src
    output: dist
    image: ghcr.io/chaotic-ground/wikven:nightly-YYYY-MM-DD
입력 기본값 하는 일
source src 구울 위키 소스가 담긴 디렉터리.
output dist 정적 사이트를 쓸 디렉터리.
image 액션이 잘려 나온 릴리스 실행할 이미지. 다른 태그로 고정하려면 덮어쓰십시오.
cache true 이미지 참조를 키로 삼아 받아 온 이미지를 실행 사이에 캐시합니다. 항상 새로 받으려면 false로 두십시오.
source-date-epoch HEAD의 커밋 시각 굽기에 쓸 SOURCE_DATE_EPOCH. 한 커밋을 몇 번 구워도 문서 날짜가 같아집니다.
jobs 프로세서당 하나 굽기에 쓸 WIKVEN_BUILD_JOBS. 스킨 렌더링을 몇 개까지 나란히 돌릴지를 정합니다. 메모리가 모자란 러너에서는 1로 한 번에 하나씩 렌더링합니다.

true나 false를 받는 입력은 — 여기서는 cache, 아래 다른 액션에서는 gate와 comment — 그 둘 말고는 받지 않습니다. 예전에는 둘 중 어느 것도 아닌 값이 false로 읽혔습니다. 그래서 setup-node와 setup-python이 값으로 캐시할 대상을 받는 철자대로 cache: npm이라고 쓰면, 아무 말 없이 캐시가 꺼졌습니다. 이제는 두 액션 모두 멈춰 서서 어느 입력인지 알려 줍니다.

액션은 소스 트리의 git log를 덤프해 빌드에 넘기기도 합니다. 각 문서가 그것을 마지막으로 바꾼 커밋의 날짜를 갖는 것이 그 덕분입니다. 그러려면 전체 역사가 필요하므로 fetch-depth: 0으로 체크아웃하십시오. 그러지 않으면 모든 문서가 빌드 중인 커밋의 날짜를 갖게 됩니다. 그런 일이 생기면 액션이 로그에 그렇게 적습니다.

check-translations 액션

소스 트리에 translate check를 실행하고, 발견한 것마다 해당 파일에 주석으로 보고합니다.

주석(annotation)은 변경사항을 읽는 사람을 위한 것입니다. 처음으로 번역을 보내는 기여자에게는 무엇을 실행해야 하는지 알려 주는 편이 낫고, comment: true가 그 일을 합니다. 풀 리퀘스트에 코멘트 하나를 남기고, 발견한 것을 문제 종류별로 묶어 각각 어떤 translate 명령으로 해결하는지 적어 줍니다. 실행할 때마다 새로 달지 않고 기존 코멘트를 고치며, 보고할 것이 없어지면 코멘트를 내립니다. 아무 문제 없다고 알리는 코멘트는 아무도 필요로 하지 않고, 기록은 어차피 주석에 남습니다. 그 기여자는 본디 다른 언어로 일하는 사람이므로 코멘트가 그 언어로 말할 수 있습니다. comment-languages: auto를 주면 영어와, 그 코멘트가 다루는 번역의 언어로 함께 쓰이며, 문구는 wikven 자신의 인터페이스 메시지에서 옵니다. 잡에 pull-requests: write 권한이 필요하고, 포크에서 온 풀 리퀘스트는 읽기 전용 토큰이라 코멘트를 건너뛰며 로그에 그 사실을 남깁니다.

- uses: chaotic-ground/wikven/actions/check-translations@nightly-YYYY-MM-DD
  with:
    source: src
    image: ghcr.io/chaotic-ground/wikven:nightly-YYYY-MM-DD
입력 기본값 하는 일
source src 검사할 위키 소스가 담긴 디렉터리.
image 액션이 잘려 나온 릴리스 실행할 이미지.
cache true 받아 온 이미지를 실행 사이에 캐시합니다.
gate true 원본 문서가 망가졌을 때 단계를 실패시킵니다. 오래되었거나 빠진 번역은 보고되기만 하고 단계를 실패시키지 않습니다.
comment false 발견한 것을 종류별로 묶고 해결할 translate 명령을 적어 풀 리퀘스트에 코멘트도 남깁니다.
comment-languages 영어만 그 코멘트를 함께 쓸 언어. auto는 발견된 것들이 다루는 언어를 쓰고, ko,fr처럼 직접 나열할 수도 있습니다.
github-token 잡 자체의 토큰 코멘트를 남길 때 쓰는 토큰.
